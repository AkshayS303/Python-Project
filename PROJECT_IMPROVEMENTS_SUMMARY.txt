[2026-10-29] – Jacobi Iterative Numerical Method & Convergence Analytics Suite
--------------------------------------------------------------------------------
CHANGE: Integrated teammate's numerical linear algebra algorithm (from project1.pdf)
        into the MatSolve engine and web platform. Bridges direct algebraic
        elimination with iterative numerical methods and statistical analytics.

MATHEMATICAL & ALGORITHMIC ADDITIONS:
  - Jacobi Iterative Method:
      • Fixed-point iteration: x_i^(k+1) = (b_i - ∑_{j≠i} A_ij x_j^(k)) / A_ii
      • Initial state vector x^(0) = [0, 0, ..., 0] with step-by-step coordinate logging.
      • Non-zero diagonal pre-check and strict diagonal dominance test:
        |A_ii| > ∑_{j≠i} |A_ij| (guarantees convergence by Gershgorin Circle Theorem).
      • Integrated determinant test det(A) and Row Echelon Form (REF) rank analysis
        via Rouché–Capelli theorem.
  - Statistical Dispersion Across Iterations (Teammate Step 7):
      • Calculates total variance (σ²) and standard deviation (σ) for each variable
        across all iteration steps to measure dispersion during convergence.
  - Running Variance vs. Std Dev Crossover Profile (Teammate Step 9):
      • Computes cumulative running variance and running standard deviation starting
        from step 2.
      • Dynamically locates sign change / zero-crossings where running σ = σ² and logs
        exact iteration index and value.
  - 3D Convergence Trajectory:
      • Records coordinates (x, y, z) across iteration indices k = 0...N.

HOW IT WORKS:
  1. Developer creates / edits `.env` in the project root:
         GEMINI_API_KEY=<your-key-here>
  2. `load_dotenv()` at the top of ai_parser.py reads this file into the
     process environment before any other code runs.
  3. `os.environ.get("GEMINI_API_KEY", "")` picks up the value.
  4. The `.env` file is git-ignored, so the real key is never committed.

SECURITY IMPACT: High – eliminates credentials in source control.

PRESENTATION TALKING POINTS — UI REDESIGN
================================================================================

1. Starting point
   The original interface was a dark, glassmorphic dashboard. The redesign
   keeps the same engine but replaces the visual language with a warm, editorial
   Riff-inspired system: thick ink outlines, hard offset shadows and a calm
   near-neutral palette of ash grey, dim grey, grey olive and deep mocha.

2. Why this direction
   MatSolve is a classroom tool, not a corporate dashboard. Hand-drawn math
   motifs — matrix brackets, a sigma medallion and an "x?" plaque — plus
   oversized display type make linear algebra feel approachable, while the
   mono-spaced equations stay precise and readable. The restrained palette means
   colour carries meaning (which state? which mode?) instead of competing with
   the maths.

3. What was restructured
   - Mode switching is now the central composition: a dim-grey card for Gemini
     word problems and an ash-grey card for direct matrix entry.
   - The workspace is framed as a two-stage "Input Deck → Solution Board" flow,
     so the screen reads like a solving process rather than two generic panels.
   - Results are colour-coded tickets and value cards, with steps as expandable
     receipts that expose every row operation.

4. Engineering decisions
   - No framework: the existing HTML/CSS/JS architecture is retained.
   - FastAPI endpoints, request shapes and every solver (four direct methods plus
     Jacobi iteration) are untouched by the UI work.
   - Colour is expressed as role tokens (--accent, --accent-2, --accent-3), so
     the palette is a single edit rather than a 350-rule find-and-replace.
   - Contrast was measured, not eyeballed: white on dim grey is 5.48:1, mocha on
     ash is 5.53:1, mocha on white is 12.96:1. Grey olive fails small-text
     contrast, so it is decoration only — never a text background.
   - Steps now use semantic <details> elements for built-in keyboard support.
   - Accessibility includes skip navigation, visible focus, ARIA tabs, a focus-
     trapped modal, reduced-motion handling and layouts verified down to 320px.
   - The Chart.js views are themed to the palette and hide automatically when
     they have nothing to plot; they are a progressive enhancement, so a missing
     CDN can never block the numeric results or step cards.
   - The Jacobi commit merged cleanly at the feature level but assumed the old
     dark theme; its CSS was re-expressed in role tokens and its divergence
     banner rebuilds the fallback button as a real DOM node instead of an
     inline-onclick HTML string, so solver messages stay text-only.
