[2026-11-19] – Fix: Unstyled/Blank UI Caused by Stale Server + Relative Asset Paths
--------------------------------------------------------------------------------
BUG: The page rendered as an unstyled document (giant blue logo artwork filling
     the screen) in Edge, Chrome and the VS Code browser, while other machines
     looked normal. /style.css and /app.js returned HTTP 404 while / and
     /static/style.css returned 200.

ROOT CAUSE:
  - index.html (rewritten in the "ui" work) references its assets with the
    short relative paths `style.css` and `app.js`, which resolve to /style.css
    and /app.js on the server root.
  - Those extra routes were added to server.py at the same time, but the
    long-running uvicorn process on port 8000 had been started before the edit
    and never reloaded. It kept serving the NEW index.html from disk (served
    per-request) while the OLD route table had no /style.css and /app.js.
  - Result: HTML 200 + CSS/JS 404 -> fully unstyled page (SVG logo expands to
    full width and inherits the default link blue). Not a device/browser bug;
    the "fine on other devices" machines were simply showing a cached copy of
    the previous HTML that still pointed at /static/style.css.

FIXES:
  - static/index.html
      - Assets now use server-absolute paths `/static/style.css` and
        `/static/app.js`, which are served by the StaticFiles mount that exists
        in every server version, so HTML and CSS can never be out of sync again.
  - server.py
      - Added `NO_CACHE = {"Cache-Control": "no-store, max-age=0"}` and applied
        it to the `/`, `/style.css` and `/app.js` responses so an older cached
        page stylesheet can never mask a fresh deploy.
  - Operation: the stale uvicorn process was restarted; /, /style.css, /app.js
    and /api/solve/matrix were all verified returning 200 with correct MIME
    types and a correct solution vector.

NOTE FOR DEMOS: after editing server.py always restart run.bat / server.py -
uvicorn does not hot-reload every change, and HTML/CSS/JS edits are not watched.

[2026-11-18] – Validation Curve: L2 Error Norm & Semi-Log Convergence Analytics
--------------------------------------------------------------------------------
CHANGE: Integrated teammate's latest algorithm update (from validation curve.pdf)
        introducing formal error validation curves for the Jacobi Iterative Method.

MATHEMATICAL & ALGORITHMIC ADDITIONS:
  - Ground-Truth Solution Reference:
      • Resolves exact benchmark solution vector x_true = A⁻¹B using direct linear
        algebra (LU decomposition / np.linalg.solve).
  - L2 Error Norm Trajectory (Step 9):
      • Formulates the Euclidean distance error metric at each iteration step k:
        e_k = ||x^(k) - x_true||_2 = sqrt( ∑_{i=1}^m (x_i^(k) - x_i_true)^2 )
      • Tracks the progression of absolute error norm from initial guess (k=0) to
        final iteration step.
  - Semi-Logarithmic Error Decay Visualization:
      • Interactive Chart.js line graph featuring a logarithmic Y-scale (base 10).
      • Mathematically demonstrates exponential convergence: on a log scale, linear
        downward slope visually confirms that error decays exponentially with respect
        to iteration index k.
      • If a system is non-diagonally dominant, the curve visually shoots upward,
        providing immediate graphical proof of divergence.
      • Displays live target accuracy pill badge with scientific exponential notation.

MATHEMATICAL & ALGORITHMIC ADDITIONS:
  - Jacobi Iterative Method:
      • Fixed-point iteration: x_i^(k+1) = (b_i - ∑_{j≠i} A_ij x_j^(k)) / A_ii
      • Initial state vector x^(0) = [0, 0, ..., 0] with step-by-step coordinate logging.
      • Non-zero diagonal pre-check and strict diagonal dominance test:
        |A_ii| > ∑_{j≠i} |A_ij| (guarantees convergence by Gershgorin Circle Theorem).
      • Integrated determinant test det(A) and Row Echelon Form (REF) rank analysis
        via Rouché–Capelli theorem.
  - Statistical Dispersion Across Iterations (Teammate Step 7):
      • Calculates total variance (σ²) and standard deviation (σ) for each variable
        across all iteration steps to measure dispersion during convergence.
  - Running Variance vs. Std Dev Crossover Profile (Teammate Step 9):
      • Computes cumulative running variance and running standard deviation starting
        from step 2.
      • Dynamically locates sign change / zero-crossings where running σ = σ² and logs
        exact iteration index and value.
  - 3D Convergence Trajectory:
      • Records coordinates (x, y, z) across iteration indices k = 0...N.

HOW IT WORKS:

         GEMINI_API_KEY=<your-key-here>

  4. The `.env` file is git-ignored, so the real key is never committed.

PRESENTATION TALKING POINTS — UI REDESIGN
================================================================================

1. Starting point
   The original interface was a dark, glassmorphic dashboard. The redesign
   keeps the same engine but replaces the visual language with a warm, editorial
   Riff-inspired system: thick ink outlines, hard offset shadows and a calm
   near-neutral palette of ash grey, dim grey, grey olive and deep mocha.

2. Why this direction
   MatSolve is a classroom tool, not a corporate dashboard. Hand-drawn math
   motifs — matrix brackets, a sigma medallion and an "x?" plaque — plus
   oversized display type make linear algebra feel approachable, while the
   mono-spaced equations stay precise and readable. The restrained palette means
   colour carries meaning (which state? which mode?) instead of competing with
   the maths.

3. What was restructured
   - Mode switching is now the central composition: a dim-grey card for Gemini
     word problems and an ash-grey card for direct matrix entry.
   - The workspace is framed as a two-stage "Input Deck → Solution Board" flow,
     so the screen reads like a solving process rather than two generic panels.
   - Results are colour-coded tickets and value cards, with steps as expandable
     receipts that expose every row operation.

4. Engineering decisions
   - No framework: the existing HTML/CSS/JS architecture is retained.
   - FastAPI endpoints, request shapes and every solver (four direct methods plus
     Jacobi iteration) are untouched by the UI work.
   - Colour is expressed as role tokens (--accent, --accent-2, --accent-3), so
     the palette is a single edit rather than a 350-rule find-and-replace.
   - Contrast was measured, not eyeballed: white on dim grey is 5.48:1, mocha on
     ash is 5.53:1, mocha on white is 12.96:1. Grey olive fails small-text
     contrast, so it is decoration only — never a text background.
   - Steps now use semantic <details> elements for built-in keyboard support.
   - Accessibility includes skip navigation, visible focus, ARIA tabs, a focus-
     trapped modal, reduced-motion handling and layouts verified down to 320px.
   - The Chart.js views are themed to the palette and hide automatically when
     they have nothing to plot; they are a progressive enhancement, so a missing
     CDN can never block the numeric results or step cards.
   - The Jacobi commit merged cleanly at the feature level but assumed the old
     dark theme; its CSS was re-expressed in role tokens and its divergence
     banner rebuilds the fallback button as a real DOM node instead of an
     inline-onclick HTML string, so solver messages stay text-only.

   a. Load the Farm Animals word problem and solve it.
   b. Expand the step cards to show the row operations.
   c. Switch to Direct Matrix, load "No solution", and show the deep-mocha
      ticket (the heaviest surface on the page, deliberately different from the
      ash "unique" ticket).
   d. Load "Jacobi dominant", pick "Jacobi iteration", and walk through the
      dominance verdict, dispersion cards, trajectory + crossover charts and the
      iteration history table.
   e. Load "Unique 3×3", compare methods, then open the Gemini key modal.
   f. Resize to phone width to demonstrate the stacked responsive layout.
